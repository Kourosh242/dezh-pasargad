# فیکس فوری 1.0.1 — دو باگ گزارش‌شده توسط کاربر (versionCode بدون تغییر: 2)

## باگ ۱ (بحرانی): آپدیت دانلود می‌شود، تأیید داده می‌شود، ولی نصب هرگز انجام نمی‌شود

**RCA (ریشه‌یابی دقیق):**
در `PackageApkInstaller`، گیرندهٔ برادکست وضعیت session با این فیلتر ثبت شده بود:

```
IntentFilter(ACTION_INSTALL_COMPLETE).apply { addDataScheme("package") }
```

در حالی که برادکستِ ما (و الگوی رسمی) فقط **action + setPackage** است و **هیچ data Uri ندارد**. در اندروید، فیلتری که data scheme الزام کرده با intentِ بدون data هرگز match نمی‌شود. نتیجهٔ زنجیره‌ای:

1. `commit()` انجام می‌شود ✓
2. سیستم `STATUS_PENDING_USER_ACTION` را برادکست می‌کند ✗ (به گیرنده نرسید)
3. پس intent پنجرهٔ رسمی تأیید هرگز launch نشد
4. اپ تا ابد در «در حال نصب… پنجرهٔ تأیید اندروید را دنبال کنید» ماند
5. هیچ نصبی انجام نشد

صفحه‌ای که کاربر به‌عنوان «تأیید نصب» دیده بود، صفحهٔ اجازهٔ «نصب برنامه‌های ناشناس» بود — نه پنجرهٔ رسمی تأیید؛ پنجرهٔ رسمی هیچ‌وقت نیامد.

**فیکس:** فیلتر بدون data scheme (`IntentFilter(ACTION_INSTALL_COMPLETE)`) + ثبت با `RECEIVER_NOT_EXPORTED` (سرویس نصاب سیستم معاف از این محدودیت است و امنیت هم بالاتر رفت).

**TDD:** تست `status filter matches our own no-data broadcast` ابتدا روی کد قدیمی **FAILED** شد (`expected:<0> but was:<1>` — شمارش scheme) و پس از فیکس سبز شد. این تست رگرسیون دائمی است.

## باگ ۲ (UI): «لکه/سایهٔ کرم‌رنگ» در ناوبری پایین

**RCA:** در دور قبل، ناوبری پایین با یک پیل سفارشیِ شناور بازنویسی شده بود (`Surface` جدا + `BoxWithConstraints` + پیل ۵۶×۳۰dp بالای آیکون‌ها). خروجی، یک لکهٔ کرم‌رنگِ جدا از آیکون بود که هنگام جابه‌جایی بین تب‌ها بالا-پایین پرش می‌کرد و مثل آرتیفکت دیده می‌شد.

**فیکس:** بازگشت کامل به `NavigationBar`/`NavigationBarItem` **استاندارد پلتفرم** — ایندیکیتور بومی M3 که آیکون فعال را داخل خود تب قاب می‌گیرد؛ بدون هیچ لایهٔ سفارشی شناور. (درس: برای مؤلفه‌های پایه، رندر بومی پلتفرم می‌برد.)

**پولیش همراه:** کانتینر کارت‌های تنظیمات یک پله کنتراست بیشتر (`surfaceContainer`) تا در تم روشن هم مرز کارت‌ها واقعاً دیده شود.
